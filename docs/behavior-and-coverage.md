# Reference scenarios: behavior and verification

The reference describes 15 scenario groups and alternatives that require a product decision. The application keeps the original vanilla browser implementation. Playwright, jsdom and axe are development dependencies only.

| Group | Implemented behavior / automated coverage |
|---|---|
| 1. Transfers | Two linked records; source/destination edits preserve direction; type changes remove old records; delete and undo operate atomically; independent net-worth assertion. |
| 2. History | 20 actions, exact mixed-action snapshots and redo reconstruction; new actions invalidate redo; empty buttons are disabled; reload resets history while retaining data. Text fields retain native undo. |
| 3. Budgets | Green below 80%, yellow at 80–100%, red strictly above the limit. Integral-cent math; parent budgets include children; transfers excluded; zero limits safe; edit/date/recategorization updates. |
| 4. Recurrence | Daily/weekly/monthly/custom; catch-up, reload/tampering deduplication, month-end anchor, leap years, one-year backlog, future rules, DST and five time zones. Rule edits preserve historical records; rule deletion preserves generated entries. A run is capped at 10,000 dates per rule to avoid unbounded hostile backlogs; remaining dates resume next launch. |
| 5. Storage | Absent/malformed/wrong-shape states recover; bad original bytes copied to the recovery key; invalid IDs/references/types rejected; preferences/page/page size normalized; 5 MB payload; visible storage failure notice. |
| 6. CSV | Comma-delimited UTF-8 with BOM, quoted commas/newlines/quotes, custom column mapping, errors for every invalid logical row, all-or-nothing writes, transfers and 5,000 rows. Reimporting intentionally creates duplicates; there is no content-based deduplication. Semicolon files are unsupported and produce validation errors. CSV row numbering counts parsed records, not physical lines inside a quoted field. Import performance budget is 15 seconds in the browser tests. |
| 7. Backups | Valid JSON replaces the complete state, with one undo step. Rich 200-record roundtrip; existing data unchanged on invalid/truncated/hostile/reference errors. File limit 10 MB; 50 MB input rejected before reading. Import runs due recurring rules; historical data remains unchanged. UI route follows the hash and is treated as volatile in roundtrip comparisons. |
| 8. Transactions | Combined inclusive date/amount filters, literal case-insensitive payee/notes/tag search, three-key stable sorting, pagination and reload persistence. Sort clicks promote a key to first priority and toggle direction; Shift is optional. Reset clears filters/sort/page/selection and preserves chosen page size. 10,000-row case renders one page. |
| 9. Bulk actions | Select all means current page; selection survives pagination. Applying/resetting filters clears selection, preventing hidden-row deletion. Transfers cannot be categorized; deleting one half removes its peer. Delete confirmation is required. Undo restores a bulk action in one step. |
| 10. Routes | Seven cold-load routes, reload, back/forward, unknown-route dashboard fallback, rapid hash changes, aria-current, and heading focus. Navigating while the CSV modal is open closes it. Same hash assignments do not append history. |
| 11. Accessibility | Skip link, file labels, row-specific action names, aria-sort, live announcements, chart descriptions, modal focus trap/Escape, heading focus, keyboard journeys, axe audits on all routes in both themes and on modal errors. |
| 12. Presentation | Light/dark × USD/INR × 375/768/1440 × seven-route screenshots; category spacing; long text; horizontal overflow checks; chart-only resizing; persistent/system theme. Currency relabels units without converting or mutating amounts. Print stylesheet and reduced-motion support. |
| 13. Dashboard | Integral-cent account/net-worth math, current-month income/expense, transfers excluded, child paths, accessible pie legend and twelve year-labeled trend months, live undo/mutation updates. Credit/loan debt is represented as a negative balance. |
| 14. Tabs/failures | Web Locks serialize initialization and mutations in supporting browsers; before each write, reconcile the latest saved financial state. Storage events update other tabs and clear stale undo stacks. UI-only saves reconcile under the same lock. Recurrence race, stale tabs, quota/unavailable storage, unsaved-transfer integrity, offline actions. Without Web Locks, reconciliation still works but simultaneous cross-process writes are not guaranteed. Offline reload depends on hosting/browser cache; no service worker is installed. |
| 15. Validation | Positive transaction amounts, nonnegative budgets, signed account openings; at most two decimal places, maximum 99,999,999,999.99. Extra decimal places are rejected rather than silently rounded. Dates require real ISO calendar dates, years 1000–9999; future dates allowed. Duplicate account names rejected case-insensitively; category names unique under the same parent; monthly budgets unique. HTML escaped, hostile JSON keys rejected, tags trimmed/exact duplicates removed, double submits do not duplicate records. |

## Browser coverage and visual baselines

The delivered suite runs Chromium, Firefox, WebKit and mobile Chrome. See verification-results.md for the completed runs. The GitHub workflow installs and runs all four projects when placed at the repository root.

Screenshot comparisons are explicit: `npm run test:e2e:visual`. The bundled baselines were created and compared on Linux with Chromium 153. Fonts, browser builds and OS can change screenshots; review and create baselines for your chosen CI environment using `npm run test:e2e:update`. Do not automatically update baselines on every PR. Standard `npm run test:e2e` captures the full visual matrix as report artifacts while running functional and accessibility checks across all configured engines.

Axe and automated keyboard checks cover many requirements; they do not substitute for human screen-reader or print/zoom review. Real-device Safari and assistive-technology checks remain human verification tasks.
